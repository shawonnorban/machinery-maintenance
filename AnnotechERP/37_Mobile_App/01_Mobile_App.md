## ১. user-এর সিদ্ধান্ত (2026-11-25)

1. অ্যাপটা আমাদের প্রজেক্টে আসবে, আগে প্ল্যান।
2. অ্যাপে থাকবে: **Quality Tally**, **Machinery**, **Order Summary** (শুধু পরিবর্তনের লগ), **Pre-Budget** (শুধু Budget Overview ও Approval), **Dev Sample Status** (শুধু পরিবর্তনের লগ)।
3. QC ঢুকবেন **কার্ড ID + PIN** দিয়ে, এবং **ইমেইল/পাসওয়ার্ড** দিয়েও।
4. লাইনে **একটা শেয়ার করা ট্যাব**।
5. annotech-rmg অ্যাপের সমস্যাগুলো এখানে সমাধান করতে হবে।

6. **প্ল্যান ও প্রশ্নের উত্তর (2026-11-25, "১-৫ হ্যাঁ"):** ধাপের ক্রম ঠিক; PIN ৬ অঙ্ক, প্রথমটা QC Assignment থেকে Owner / Factory Admin / Management দেন; ট্যাব একটা লাইনে বাঁধা; নেট ছাড়া শুধু ওই ট্যাবে গত ৭ দিনে ঢোকা QC ঢুকতে পারেন; নাম "Annotech ERP" (`com.annotech.erp`), প্রথমে APK সরাসরি ট্যাবে, পরে Play Store।

7. **ধাপ ১-এর আগে (2026-11-25), উপরের যেখানে আলাদা সেখানে এটাই চলবে:** লগইনে **Company Code** (কোম্পানি সেট করার সময় দেওয়া কোড) + **QC ID = Employee ID** (`hr_employees.employee_code`, কার্ড নম্বর নয়) + PIN; **ডিফল্ট PIN `000000`**, পরে বদলানো যাবে (প্রথমবারে বাধ্য নয়, অ্যাপ সতর্ক করে); পর্দা **মোবাইলের** (খাড়া), ট্যাবের নয়; অ্যাপ সরাসরি সার্ভারের **IP ও পোর্টে** যুক্ত হয় (HTTP)।

8. **ধাপ ২-এর আগে (2026-11-26):** কাটিং QC কার্ড স্ক্যান করবেন **ফোনের ক্যামেরায়**; ইমেইল লগইনের সীমা **বাড়ানো** (সবার মিলিয়ে মিনিটে ১০টা ছিল); ধাপ ২ শুরু।

## ২. এখন কী আছে, কী নেই

কোড ও ডাটাবেস দেখে যাচাই করা।

| বিষয় | আছে | বানাতে হবে |
|---|---|---|
| লগইন | `POST /auth/login` (ইমেইল বা User ID), টোকেনে কোম্পানি ও ability | কার্ড ID + PIN লগইন; ট্যাব নিবন্ধন |
| কার্ড ID | HR-এ ১৩১ এমপ্লয়ীর সবার আলাদা `card_no`; `users.employee_code` দিয়ে ১২৭ ইউজার HR-এর সাথে মেলে | PIN রাখার জায়গা, PIN দেওয়া/বদলানো |
| ডেমো QC | ৪ জন QC, কারো HR employee যুক্ত নেই | QC Assignment থেকে যুক্ত করা (PIN লগইনের শর্ত) |
| Quality Tally | context, tap, bulk, undo, summary, cut-bundles, targets, dashboard | ফিরিয়ে দেওয়া ট্যাপের তালিকা; দেরিতে আসা ট্যাপের নিয়ম (§৫) |
| Machinery | asset, `scan/assets/{code}`, breakdown-এর সব ধাপ, work order, checklist, labor, parts, PM schedule, meter; লেখার পথে `Idempotency-Key` | মোবাইলের জন্য নতুন API লাগবে না |
| Order Summary লগ | `GET /order-summary/audit-log` (বায়ার অনুযায়ী সীমিত, ফিল্টার, পাতা) | কিছু না |
| Dev Sample লগ | টেবিল `ds_changes`-এ সব পরিবর্তন জমা হয় | **লগের API নেই, বানাতে হবে**; ওয়েবেও এই পাতা নেই |
| Pre-Budget | `budgets/{no}/overview`, `budgets/finalized`, `budgets/{no}`, `budgets/{no}/decision` | কিছু না |
| নোটিফিকেশন | ইন-অ্যাপ তালিকা; সব নোটিফিকেশন এক জায়গা (`NotificationDispatcher`) দিয়ে যায় | মোবাইল push (Firebase) |
| ভাষা | `frontend/messages/{en,bn}` | অ্যাপ এগুলোই পড়বে, কপি হবে না |

### সার্ভারে যা আগে ঠিক করতে হবে

- **লগইনের সীমা ফ্লোরে আটকে দেবে।** এখন এক IP থেকে মিনিটে ১০ লগইন (`api-auth`), সাথে `AttemptLogin`-এ IP প্রতি ২০। কারখানার সব ট্যাবের IP একটাই, শিফট শুরুতে ৩০ জন QC ঢুকলে বাকিরা আটকে যাবেন। PIN লগইনের সীমা হবে **ট্যাব + কার্ড ID** ধরে।
- **নেট ছাড়া করা ট্যাপ ভুল কারণে ফিরে যেতে পারে।** সুইংয়ের ট্যাপ আগে আর কাটিংয়ের ট্যাপ পরে সার্ভারে এলে সুইংয়েরটা "প্রস্তুত নেই" বলে বাদ যাবে, যদিও ফ্লোরে কাজ ঠিকই হয়েছে। সমাধান §৫-এ।

## ৪. অ্যাপে কে কী দেখবেন

পারমিশন ও কোম্পানিতে মডিউল চালু থাকা ধরে। যা করতে পারবেন না, তা দেখাবে না; সিদ্ধান্ত সব সময় সার্ভারের।

### ৪.১ QC (শেয়ার করা ট্যাব)
- **ঢোকা:** কার্ড ID + PIN। শুধু Quality Tally দেখেন।
- **ট্যালি:** সুইং/কোয়ালিটি: জব, ৪ বোতাম, টার্গেট, ঘণ্টাভিত্তিক হিসাব। কাটিং: ক্যামেরায় বা স্ক্যানারে কার্ড, প্যানেল, ৪ বোতাম।
- **Undo:** না-পাঠানো ট্যাপ ফোনেই ফেরত; পাঠানো ট্যাপ সার্ভার থেকে।
- **উপরে সব সময়:** কে ঢুকে আছেন, কত ট্যাপ অপেক্ষায়, নেট আছে কি না, **QC বদল** বোতাম।
- **লক:** কিছুক্ষণ ব্যবহার না হলে পর্দা লক, একই QC PIN দিয়ে ফেরেন।

### ৪.২ সেকশন ম্যানেজার (নিজের ফোন)
- নিজের সেকশনের Dashboard, Line Target (Pending orders ও Give target), History।
- কাটিং ম্যানেজার: **Cutting Input ক্যামেরায় স্ক্যান** (একটার পর একটা) ও ম্যানুয়াল।
- "গৃহীত হয়নি" ট্যাপের তালিকা।
- Jobs, QC Assignment, Panels, Defect Types, Attendance ওয়েবেই থাকে।

### ৪.৩ Machinery
| ভূমিকা | অ্যাপে |
|---|---|
| Line Chief | মেশিন স্ক্যান, ব্রেকডাউন রিপোর্ট (ছবিসহ), Verify, Submit for Approval |
| Technician | My Work, Start / Hold / Resume / Complete, চেকলিস্ট, সময়, পার্টস, root cause, ছবি |
| Maintenance Engineer / Manager | Acknowledge, Assign, Close / Reject, খোলা তালিকা, Dashboard |
| অন্যরা (view) | মেশিনের তালিকা, বিস্তারিত, PM schedule, meter reading |

মেশিন নিবন্ধন, PM প্ল্যান, টেমপ্লেট, স্টক ও মাস্টার ওয়েবেই থাকে। ব্রেকডাউন রিপোর্ট, চেকলিস্ট ও সময় অফলাইনে জমা থেকে পরে যাবে (`Idempotency-Key` আছে, দুইবার হবে না)।

### ৪.৪ Order Summary ও Dev Sample Status: শুধু লগ
কখন, কে, কোন অর্ডার/স্যাম্পল, কোন কলাম, আগে → পরে। ফিল্টার: তারিখ, ধরন (নতুন/এডিট/মোছা), ইউজার, খোঁজ। যাঁর যে বায়ার, শুধু সেগুলো। এডিট বা শিট নেই।

### ৪.৫ Pre-Budget: শুধু Overview ও Approval
- বাজেটের তালিকা → **Budget Overview**: স্টাইলপ্রতি কার্ড (ছবি, Job No, Item, Color, Size, Qty, FOB, Value, RFI/SD) ও মোট।
- **Approval:** কোন ধাপে আছে, কে কী বলেছেন, Approve / Reject (Reject-এ কারণ বাধ্যতামূলক)। ধাপ যাঁর, বোতাম শুধু তাঁর।

### ৪.৬ সবার জন্য
নোটিফিকেশন ও push, ভাষা (বাংলা/ইংরেজি), লাইট/ডার্ক, পাসওয়ার্ড বদল, সাইন আউট।

## ৫. সার্ভারের কাজ

1. **PIN:** `users`-এ PIN-এর হ্যাশ। QC Assignment পাতায় Owner / Factory Admin / Management প্রথম PIN দেন; প্রথমবার ঢুকে QC নিজের PIN বসান। ৬ অঙ্ক; সহজ PIN (111111, 123456) নেওয়া হয় না; ৫ বার ভুলে ১৫ মিনিট লক; সব চেষ্টা লগে।
2. **কার্ড ID → ইউজার:** কার্ড ID = HR `card_no` (Employee ID-ও চলবে) → QC Assignment-এ যুক্ত HR employee → ইউজার। বন্ধ ইউজার বা সক্রিয় নয় এমন এমপ্লয়ী ঢুকতে পারেন না।
3. **PIN সেশন:** শুধু ট্যালির অনুমতি (টোকেন ability), সর্বোচ্চ ১৪ ঘণ্টা। PIN দিয়ে ঢুকে ম্যানেজারের কাজ, বাজেট বা রিপোর্ট খোলে না, ইউজারের রোল যা-ই হোক।
4. **ট্যাব নিবন্ধন:** Owner / Factory Admin / Management ট্যাবে একবার ইমেইলে ঢুকে কোম্পানি, কারখানা ও (চাইলে) লাইন বসান। ওয়েবে **Tablets** পাতা: তালিকা, শেষ দেখা, অ্যাপের সংস্করণ, অপেক্ষমাণ ট্যাপ, বন্ধ করা। হারানো ট্যাব বন্ধ করলে আর কিছু পাঠাতে পারে না।
5. **ট্যাপ পাঠানো:** `tally/bulk` ট্যাবের পরিচয়ে আসে, প্রতিটি ট্যাপে QC-র সেশন থাকে; সার্ভার মিলিয়ে দেখে ওই সময়ে ওই QC ওই ট্যাবে ছিলেন কি না।
6. **দেরিতে আসা ট্যাপ:** নেট ছাড়া করা ট্যাপে "প্রস্তুত নেই" বা "টার্গেট নেই" হলে বাদ যাবে না; গৃহীত হয়ে **Review** চিহ্ন পায়, ম্যানেজার দেখেন। বন্ধ জব, অন্যের লাইন, ৩ দিনের বেশি পুরনো হলে ফেরত, কারণসহ জমা।
7. **Dev Sample লগ API**; ওয়েবেও একই পাতা (Order Summary-র Audit Log-এর মতো)।
8. **Push:** ফোনের টোকেন লগইনের সাথে বাঁধা (সাইন আউটে মুছে যায়), PIN সেশনে push নেই। Firebase-এর চাবি Platform পাতায়, encrypted।
9. **লগইনের সীমা** ট্যাব + কার্ড ID ধরে (§২)।
10. **অ্যাপের সংস্করণ:** সার্ভার ন্যূনতম সংস্করণ বলে; পুরনো অ্যাপ "আপডেট করুন" দেখায়, না-পাঠানো ট্যাপ আগে পাঠিয়ে।

## ১০. খোলা প্রশ্ন

1. **Push-এর Firebase:** নতুন Firebase প্রজেক্ট user-এর Google অ্যাকাউন্টে খুলতে হবে (ধাপ ৬-এর আগে)। Push-এ ফোনের ইন্টারনেটও লাগবে, শুধু কারখানার LAN-এ চলবে না।
2. **সার্ভারের IP বদলায় কি না:** সার্ভারের IP স্থির (static) হতে হবে, আর Windows Firewall-এ ৮০১০ পোর্ট খোলা। IP বদলালে সব ফোনে আবার লিখতে হবে।

  - **ইমেইলে ঢোকা QC:** `POST mobile/attach` — ফোন থেকে ইমেইল টোকেন হলে, ইউজার সক্রিয় QC হলে, অনুমোদিত ফোনে QC সেশন খোলে (PIN সাইন-ইনের মতো)। QC না হলে `NOT_QC`, অনুমোদন বাকি থাকলে `PHONE_PENDING` (হোমে কোড দেখায়)।
